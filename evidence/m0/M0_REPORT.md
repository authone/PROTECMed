## Input and output contracts
Input: OpenFHE v1.5.1 upstream source, reviewed profile `bgv-count-nofn-v2`
(`config/crypto-profile.json`), delivered smoke source `reference/cpp/count_smoke.cpp`.
Output: pinned commits, build log, CMake cache, effective 2/2 and 3/3 parameter records,
exact synthetic sums.

## Security and arithmetic invariants checked
- `SetThresholdNumOfParties(n)` present and equal to the party count in both profiles.
- `NOISE_FLOODING_MULTIPARTY` preserved; secure automatic parameter selection preserved
  (`ring_dimension` 8192 at `HEStd_128_classic`; no forced small ring, no insecure override).
- `FLEXIBLEAUTOEXT`, `UNIFORM_TERNARY`, `BV`, digit size 10, plaintext modulus 65537,
  multiplicative depth 0 — all as specified in §2.2.
- No evaluation-multiplication or automorphism keys are generated by the profile.
- Exact integer sums, including the `n * 10000` upper bound (20000 for 2/2, 30000 for 3/3)
  and the all-zero case.
- No combined secret key is constructed; `ShareKeys`, `RecoverSharedKey` and the
  private-key-vector `MultipartyKeyGen` overload are absent from every program built here.

## Exact commands
```
git clone --branch v1.5.1 --depth 1 --recurse-submodules \
  https://github.com/openfheorg/openfhe-development.git vendor/openfhe
cmake -S vendor/openfhe -B build/openfhe -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX="$PWD/.local/openfhe" -DBUILD_EXAMPLES=ON -DBUILD_UNITTESTS=OFF \
  -DBUILD_BENCHMARKS=OFF -DWITH_OPENMP=OFF -DNATIVE_SIZE=64
cmake --build build/openfhe --parallel 2 && cmake --install build/openfhe
cmake -S reference/cpp -B build/smoke -DCMAKE_PREFIX_PATH="$PWD/.local/openfhe"
cmake --build build/smoke --parallel 2
ctest --test-dir build/smoke --output-on-failure
cmake -S tools/m0-profile -B build/m0-profile -DCMAKE_PREFIX_PATH="$PWD/.local/openfhe"
cmake --build build/m0-profile --parallel 2
./build/m0-profile/profile_dump gen 2 <ctx> ; ./build/m0-profile/profile_dump inspect <ctx>
```
`LD_LIBRARY_PATH=$PWD/.local/openfhe/lib` is required to run the binaries from this
non-system prefix.

Identical for 2/2 and 3/3 except the threshold field and the first RNS modulus:

| Field | n=2 | n=3 |
|---|---|---|
| ring dimension / cyclotomic order | 8192 / 16384 | 8192 / 16384 |
| plaintext modulus | 65537 | 65537 |
| tower count | 4 | 4 |
| first RNS modulus | 2147565569 | 4295049217 |
| `GetThresholdNumOfParties()` | 2 | 3 |
| security level | `HEStd_128_classic` | `HEStd_128_classic` |
| multiparty mode | `NOISE_FLOODING_MULTIPARTY` | `NOISE_FLOODING_MULTIPARTY` |
| scaling / key switch | `FLEXIBLEAUTOEXT` / `BV` | `FLEXIBLEAUTOEXT` / `BV` |

**Serialization finding (§2.2 open question, now answered for this build):** every profile
getter above survives `SerType::BINARY` context serialization and reload **in a separate
process**, including `GetThresholdNumOfParties`, `GetMultipartyMode`, `GetSecretKeyDist`,
`GetStdLevel`, `GetScalingTechnique` and `GetKeySwitchTechnique`. The M2 worker can
therefore check the deserialized context against the compiled profile using these getters.
This is a property of the pinned v1.5.1 build recorded here, not a general guarantee, and
it does not remove the requirement to bind the profile through the signed plan as well.

## Deviations from the written gate
1. **CMake was not available system-wide.** No `cmake` package is installed and the account
   cannot install one. CMake 4.4.3 was installed with `pip` into `.local/toolchain` (ignored)
   and used for every configure/build. OpenFHE requires >= 3.16.3 and configured cleanly.
   A reviewer wanting byte-identical reproduction should record the CMake version used.
2. **A new M0 evidence tool was added** (`tools/m0-profile/`) because §7.1 requires capturing
   effective 2/2 and 3/3 profiles and the delivered smoke program prints only the ring
   dimension. It generates no keys, reads no data and is not product code. `reference/cpp/`
   was left byte-identical to the delivered kit.
3. The upstream serialization example needs a `demoData/` directory next to the binary; it
   was created before the successful rerun. Its first invocation failed with exit 1 and that
   failure is kept in `upstream-examples.log`.
